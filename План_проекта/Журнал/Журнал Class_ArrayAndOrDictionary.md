## Class_ArrayAndOrDictionary

Путь: `res://Class/Class_ArrayAndOrDictionary.gd`
Наследует: `Node`
Класс: `Class_ArrayAndOrDictionary`
Зависит от: [[Class_Help]] (создаёт свой экземпляр `Class_Help = load("res://Class/Class_Help.gd").new()`)

### Для чего нужен
Набор функций для сравнения, слияния и обхода массивов и словарей — в том числе вложенных друг в друга произвольно глубоко. Это «движок сравнения данных», который проверяется тестовым скриптом `test.gd` (рабочая зона, отдельно не описан) и используется в системе UI через [[Class_UI#fC_Mass_Creating_Node_CrTr]].

### Функции

#### fL_CompareArrays_Tr(array1, array2)
- Назначение: сравнить два массива на полное совпадение — одинаковые элементы в одинаковом порядке.
- Как пользоваться: `fL_CompareArrays_Tr([1,2,3], [1,2,3])` → `true`.
- Входные данные: `array1: Array`, `array2: Array`.
- Выходные данные: `bool` — `true`, если массивы идентичны.
- Принцип работы: сначала сравнивает длины (если разные — сразу `false`), затем поэлементно сравнивает по индексам.

#### fL_CompareArraysUnordered_Tr(array1, array2)
- Назначение: сравнить два массива на одинаковый состав элементов, но без учёта порядка (например, `[1,2]` и `[2,1]` считаются совпадающими).
- Как пользоваться: `fL_CompareArraysUnordered_Tr([1,2], [2,1])` → `true`.
- Входные данные: `array1: Array`, `array2: Array`.
- Выходные данные: `bool`.
- Принцип работы: считает, сколько раз каждый элемент встречается в первом массиве (словарь «элемент → количество»), затем вычитает по второму массиву; если что-то ушло в минус или не найдено — `false`.

#### fxL_MergeCallback_Tr(vLS_Key, v_, vLD_External)
- Назначение: callback для переноса значения по одному ключу из одного словаря в другой (в том числе вложенно, если оба значения — словари).
- Как пользоваться: не вызывается напрямую руками — передаётся как `"func"` в параметрах обхода (см. [[Class_Help#FunctionCall]]); сама структура `vLD_External` содержит `"Target_D"` (куда пишем) и `"Source_D"` (откуда берём).
- Входные данные: `vLS_Key: String` — текущий ключ; `v_` — текущее значение; `vLD_External: Dictionary` — `{"Target_D": Dictionary, "Source_D": Dictionary}`.
- Выходные данные: `Array` вида `[[продолжать, продолжать_цикл, идти_глубже], значение_для_углубления]`.
- Принцип работы: если ключ есть в источнике — либо переносит значение как есть, либо (если оба значения словари) готовит поддерево для рекурсивного слияния и просит «идти глубже».

#### fG_MergeDictionariesRecursive_Cr(Dict1, Dict2)
- Назначение: слить два словаря в один рекурсивно, с приоритетом второго словаря при конфликте ключей.
- Как пользоваться: `fG_MergeDictionariesRecursive_Cr({"a":1,"b":{"x":1}}, {"b":{"x":2,"y":3}})` → `{"a":1, "b":{"x":2,"y":3}}`.
- Входные данные: `Dict1: Dictionary` — базовый; `Dict2: Dictionary` — приоритетный (его значения побеждают при конфликте).
- Выходные данные: `Dictionary` — итоговый объединённый словарь.
- Принцип работы: делает глубокую копию `Dict1`, затем для каждого ключа `Dict2` — если оба значения словари, сливает их рекурсивно этой же функцией, иначе просто перезаписывает; новые ключи добавляет как есть.
- Отличается от более простого [[Class_Json#fxG_MergeJsonFiles_Tr]] тем, что уходит вглубь вложенных словарей, а не только по верхнему уровню ключей.

#### fC_OvergrowthIf_Tr(vLD_FirstVariable, vLS_func, PathArray = [])
- Назначение: пройти по словарю (в том числе вложенному) и на каждом ключе вызвать переданную функцию, при этом сама функция управляет обходом через три флага-ответа.
- Как пользоваться: передать словарь для обхода и `{"func": <Callable>, "Parametrs": [...]}` — на каждый ключ будет вызван [[Class_Help#FunctionCall]] с этим описанием плюс текущим путём (`PathArray`).
- Входные данные: `vLD_FirstVariable: Dictionary`; `vLS_func: Dictionary` — описание callback-а; `PathArray: Array` — накопленный путь по ключам (по умолчанию пустой).
- Выходные данные: нет (void), результат — побочные эффекты внутри callback-а.
- Принцип работы: для каждого ключа добавляет его в `PathArray`, вызывает callback через [[Class_Help#FunctionCall]]; результат — `[Продолжать_весь_обход, Продолжать_этот_цикл, Идти_глубже]`; в зависимости от флагов — останавливает весь обход, прерывает текущий уровень или рекурсивно уходит вглубь.
- Точная копия этого же кода лежит в [[Class_Logger#fC_OvergrowthIf_Tr]].

#### UniversalBypass(variables, funcparametrs, PathArray = [])
- Назначение: то же самое, что `fC_OvergrowthIf_Tr`, но универсальнее — работает с любой перебираемой структурой (не только словарь, но и массив), а управление обходом идёт через текстовые команды, а не флаги.
- Как пользоваться: передать структуру данных и `{"func": <Callable>, "Parametrs": [...]}`; callback должен вернуть одну из строк: `"Deeper"` (зайти внутрь текущего элемента), `"Further"` (перейти к следующему элементу того же уровня), `"Higher"` (прекратить обход текущего уровня).
- Входные данные: `variables` — любая структура (`Array`/`Dictionary`/др.); `funcparametrs: Dictionary` — описание callback-а; `PathArray: Array` — путь (по умолчанию пустой).
- Выходные данные: нет напрямую — данные меняются внутри переданной структуры/через callback.
- Принцип работы: копирует структуру, если она перебираемая; получает ключи через [[Class_Help#get_iter_keys]]; если ключей нет — вызывает callback один раз для самого значения; если есть — перебирает и на каждый элемент вызывает callback через [[Class_Help#FunctionCall]], обрабатывая ответ `"Deeper"/"Further"/"Higher"`.
- Используется как основа сравнения в [[#fC_ComparisonsOf2Variables_0101]] через внутренний callback [[#_C_ComparisonsOf2Variables_0101]].

#### PassageAlongWay(Variables1, PathArray, FuncParametrs = {})
- Назначение: дойти по указанному пути ключей/индексов вглубь структуры и вернуть значение, лежащее там; путь можно кастомизировать через callback.
- Как пользоваться: `PassageAlongWay({"a": {"b": 5}}, ["a", "b"])` → `5`. Если нужен нестандартный проход (например, пропуск определённых ключей) — передать `FuncParametrs` с `"func"`.
- Входные данные: `Variables1` — структура данных; `PathArray: Array` — список ключей по порядку; `FuncParametrs: Dictionary` — необязательный callback для управления проходом.
- Выходные данные: значение (`Variant`), найденное по пути.
- Принцип работы: делает глубокую копию структуры; на каждом шаге пути, если задан `FuncParametrs`, спрашивает callback (через [[Class_Help#FunctionCall]]), нужно ли реально «спускаться» по этому ключу (`flagPassageAlongWay`) — если нет, шаг пропускается.
- Используется в: [[#_C_ComparisonsOf2Variables_0101]] (получение актуальных значений при сравнении) вместе с [[#_PAW_CO2V]].

#### CheckingPath(PathArray, FuncParametrs, Variables)
- Назначение: пройтись по пути «от текущего узла вверх к корню» и на каждом уровне вызвать callback — используется, чтобы пересчитать/обновить родительские узлы после изменения дочернего.
- Как пользоваться: передать текущий путь, описание callback-а и структуру данных — на каждом шаге вверх будет вызван [[Class_Help#FunctionCall]] с результатом [[#PassageAlongWay]] для укороченного пути.
- Входные данные: `PathArray: Array`; `FuncParametrs: Dictionary`; `Variables` — структура данных.
- Выходные данные: нет.
- Принцип работы: копирует путь, в цикле убирает последний элемент и вызывает callback для получившегося укороченного пути, пока путь не станет длиной 1.
- Используется в: [[#_C_ComparisonsOf2Variables_0101]] вместе с [[#_CP_CO2V]] — пересчитывает итоговый код различия у родительских узлов после сравнения дочерних.

#### fC_ComparisonsOf2Variables_0101(Variables1, Variables2, ReturnDictionary)
- Назначение: главная функция глубокого сравнения двух любых переменных — если они не равны напрямую, но обе являются контейнером (словарь/массив), сравнивает их содержимое поэлементно и рекурсивно.
- Как пользоваться: `fC_ComparisonsOf2Variables_0101({"x":1}, {"x":2}, result)` — результат сравнения запишется в `result` (передаётся как словарь, который функция дополняет).
- Входные данные: `Variables1`, `Variables2` — любые значения для сравнения; `ReturnDictionary` — словарь, куда пишется результат.
- Выходные данные (через `ReturnDictionary`): словарь формата `{"result": "код", "Values": [Variables1, Variables2], "Child": {...}}`, где `Child` есть только если сравнение ушло на уровень ниже.
- Коды результата: `"+"` — полностью совпадают; `"-"` — различаются и не являются контейнерами (либо типы не совпали); `">"` — ключ/элемент есть только в первой переменной; `"<"` — только во второй; `"~"` — оба контейнеры, но есть различия внутри (и есть `Child` с детализацией).
- Принцип работы:
	1. если типы и значения полностью совпали — код `"+"`;
	2. если оба — словари, для каждого ключа определяет, есть ли он в обоих или только в одном (заготавливает `Child`), помечает `"~"` и запускает [[#UniversalBypass]] с внутренним callback-ом [[#_C_ComparisonsOf2Variables_0101]] для рекурсивного сравнения дочерних узлов;
	3. то же самое для массивов (по индексам, до длины меньшего массива — попарно, «лишние» элементы длинного массива помечаются `>`/`<`);
	4. иначе — `"-"`.
- Именно эту функцию гоняет на корректность и производительность скрипт `test.gd` (рабочая зона, отдельно не описан).

#### _C_ComparisonsOf2Variables_0101(InputArray)
- Назначение: внутренний callback, который [[#UniversalBypass]] вызывает на каждом шаге обхода `ReturnDictionary`, чтобы досравнить актуальные значения на этом уровне пути и решить, идти ли глубже.
- Как пользоваться: не вызывается напрямую — передаётся в `UniversalBypass` как `"func"` внутри [[#fC_ComparisonsOf2Variables_0101]].
- Входные данные: `InputArray: Array` — стандартный набор параметров обхода `UniversalBypass` (тип, структура, путь, доп. параметры, ключ).
- Выходные данные: строка-команда для `UniversalBypass` — `"Further"` (сравнение на этом уровне завершено) или `"Deeper"` (нужно спуститься ещё).
- Принцип работы: если текущий обходимый ключ — `"Child"`, получает актуальные `Variables1`/`Variables2` по пути через [[#PassageAlongWay]] (с помощью [[#_PAW_CO2V]], который умеет пропускать служебный ключ `"Child"`), сравнивает их так же, как в [[#fC_ComparisonsOf2Variables_0101]], и при полном совпадении/различии вызывает [[#CheckingPath]] с callback-ом [[#_CP_CO2V]], чтобы пересчитать код результата у родителей.

#### _CP_CO2V(PathArray, Variables)
- Назначение: пересчитывает итоговый код различия (`+ - > < ~ ~- ~> ~<`) у узла на основе того, какие коды получили его дочерние элементы.
- Как пользоваться: вызывается автоматически из [[#CheckingPath]] в процессе работы [[#_C_ComparisonsOf2Variables_0101]].
- Входные данные: `PathArray` — не используется внутри тела функции; `Variables: Dictionary` — узел результата сравнения с ключом `"Child"`.
- Выходные данные: нет — меняет `Variables["result"]` «на месте».
- Принцип работы: считает, сколько дочерних элементов получили каждый из кодов (`+`, `-`, `>`, `<`, `~...`), и по комбинации подбирает итоговый код для родителя — например, если есть и полностью совпавшие, и различающиеся по значению дети, родитель получает `"~-"`.

#### _PAW_CO2V(Array)
- Назначение: вспомогательный callback для [[#PassageAlongWay]], который при сравнении заставляет пропускать служебный ключ `"Child"` (не спускаться в него как в обычный путь).
- Как пользоваться: передаётся как `"func"` в `FuncParametrs` при вызове `PassageAlongWay` из [[#_C_ComparisonsOf2Variables_0101]].
- Входные данные: `Array` — стандартный набор параметров `PassageAlongWay` (`[VariablesReturn, Variables1, elPA]`).
- Выходные данные: `{"flagPassageAlongWay": false}`, если текущий ключ пути — `"Child"` (иначе ничего не возвращает, и шаг проходит как обычно).
- Принцип работы: проверяет `elPA` (текущий ключ шага) — если это `"Child"`, запрещает реальный спуск по этому ключу.

> ⚠️ Несостыковка: [[Class_UI#fC_Mass_Creating_Node_CrTr]] вызывает `Class_ArrDict.fC_Overgrowth_tree_Tr`, но в этом файле функция называется `fC_OvergrowthIf_Tr` — имени `fC_Overgrowth_tree_Tr` в файле нет.
