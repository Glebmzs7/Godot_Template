## Class_Json

Путь: `res://Class/Class_Json.gd`
Наследует: `Object`
Класс: `Class_Json`
Версия оформления в файле: 0.1.2

### Для чего нужен
Чтение и запись JSON-файлов на диск — используется там, где нужно сохранять/загружать данные приложения (папка `Save/`, например `Save/ChechList/*.json`, `Save/Medical_Documents/Yellow_Pages/*.json`, `Save/Settings.json`).

### Переменные

#### vGS_LastPath
`String` — путь последнего файла, с которым работали (загружали или сохраняли). Нужен для [[#fxG_OverwriteLastJson_Ch]].

#### vGD_LastJson
`Dictionary` — содержимое последнего загруженного/сохранённого JSON.

### Функции

#### fxG_LoadJson_Cr(vGS_Path)
- Назначение: прочитать JSON-файл с диска и превратить в словарь.
- Как пользоваться: `fxG_LoadJson_Cr("res://Save/Settings.json")` → словарь с содержимым файла (или `{}`, если файла нет / это не словарь).
- Входные данные: `vGS_Path: String` — путь к `.json`-файлу.
- Выходные данные: `Dictionary`.
- Принцип работы: открывает файл на чтение, читает как текст, парсит через `JSON.parse_string`; если результат — не словарь или файл не открылся, пишет ошибку и возвращает `{}`; при успехе запоминает путь и содержимое в `vGS_LastPath` / `vGD_LastJson`.

#### fxG_SaveJson_Ch(vGS_Path, vGD_Data)
- Назначение: сохранить словарь в JSON-файл.
- Как пользоваться: `fxG_SaveJson_Ch("res://Save/Settings.json", {"volume": 0.8})`.
- Входные данные: `vGS_Path: String` — путь для сохранения; `vGD_Data: Dictionary` — данные.
- Выходные данные: нет.
- Принцип работы: сначала проверяет, что папка назначения существует (`DirAccess.dir_exists_absolute` от `vGS_Path.get_base_dir()`) — если нет, пишет в лог понятную ошибку и ничего не делает; иначе открывает файл на запись, сериализует словарь через `JSON.stringify` (с отступом табом), записывает, запоминает путь и данные как «последние».
- ⚠️ **2026-08-24, найден и починен баг** («не проходит последняя проверка ThirdPartyFiles», при любом реальном состоянии файлов): `FileAccess.open(путь, FileAccess.WRITE)` в Godot 4 **не создаёт недостающие родительские папки сам** — если папки на диске нет, `open()` тихо возвращает `null` (уходит `push_error` в лог, но без указания причины, и приложение работает дальше как ни в чём не бывало). Ровно это происходило с `res://Save/Server/FileManifest.json` — папки `Save/Server/` не существовало на устройстве, поэтому `test.gd::fC_RegenerateFileManifest_Ch` ничего не сохранял, а сервер потом загружал **пустой** manifest (`{}`) и помечал вообще все присланные клиентом файлы как «Unexpected» — проверка проваливалась гарантированно.
	- ⚠️ По решению пользователя функция НЕ создаёт папку автоматически (папки создаются осознанно, руками) — вместо этого теперь заранее проверяет её существование и, если папки нет, пишет в лог однозначную ошибку с указанием именно отсутствующей папки (раньше была только общая «не удалось открыть для записи», из которой причина не видна). Папка `Save/Server/` для `FileManifest.json` уже создана вручную на устройстве пользователя (с плейсхолдером `FileManifest.json` = `{}` внутри — перезапишется сам при первом запуске сервера). Та же скрытая проблема ждала и `Class_InternetServer.FileUsers_S` — он тоже пишется через этот метод, в свою отдельную (пока не заводимую) папку.

#### fxG_OverwriteLastJson_Ch(vGD_NewData)
- Назначение: быстро пересохранить новые данные по тому же пути, что использовался в последний раз.
- Как пользоваться: сначала один раз вызвать [[#fxG_LoadJson_Cr]] или [[#fxG_SaveJson_Ch]], затем `fxG_OverwriteLastJson_Ch(новые_данные)`.
- Входные данные: `vGD_NewData: Dictionary`.
- Выходные данные: нет.
- Принцип работы: если `vGS_LastPath` пуст — ошибка («нет пути для перезаписи»); иначе вызывает [[#fxG_SaveJson_Ch]] с запомненным путём.

#### fxG_MergeJsonFiles_Tr(vGS_Source, vGS_Target, vBv_Overwrite = true)
- Назначение: объединить два JSON-файла — данные из источника переносятся в целевой файл.
- Как пользоваться: `fxG_MergeJsonFiles_Tr("res://Save/A.json", "res://Save/B.json")` — после вызова файл B будет содержать объединённые данные (при конфликте ключей побеждает источник, если `vBv_Overwrite = true`).
- Входные данные: `vGS_Source: String` — путь к исходному JSON; `vGS_Target: String` — путь к целевому JSON; `vBv_Overwrite: bool` — перезаписывать ли уже существующие в целевом файле ключи (по умолчанию `true`).
- Выходные данные: `Dictionary` — итоговое содержимое целевого файла (оно же уже записано на диск).
- Принцип работы: загружает оба файла через [[#fxG_LoadJson_Cr]]; для каждого ключа источника — если в целевом словаре его нет либо разрешена перезапись — переносит значение; сохраняет результат через [[#fxG_SaveJson_Ch]] и возвращает его.
- Отличие от [[Class_ArrayAndOrDictionary#fG_MergeDictionariesRecursive_Cr]]: здесь слияние только на верхнем уровне ключей, во вложенные словари функция не спускается.
