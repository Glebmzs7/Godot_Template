# Class_Logger

## Назначение
Логирование программы **потоками**. Поток — независимая цепочка событий (экран, загрузка, фоновая операция), которая не пересекается с другими до своего завершения; параллельно может идти сколько угодно потоков. Цели:
- находить ошибки по накопленным данным;
- восстанавливать место в коде, где что-то пошло не так;
- в перспективе — реплей (воспроизведение хода программы).

## Как подключать
Автозагрузка: `Logger = "*res://Godot_Template/Class_Logger.gd"` в `project.godot`. Во всём проекте используется **один общий экземпляр** через глобальное имя `Logger`. Отдельные экземпляры через `load(...).new()` больше не создаются: так все записи попадают в один файл сессии, это проверяет [[Сцена TestLogger]].

## Как пользоваться
1. **Один раз при старте программы** — `Logger.fxG_StartingLogger_CrTr()` (сейчас это делает [[Сцена Start_Program]]).
2. В начале независимой цепочки задач — `var id = Logger.fC_RegisterStream_Cr("ИмяПотока")`.
3. В каждой интересной точке — `Logger.fC_Adding_Buffer_Cr(id, "что произошло", [значения], доп_инфо)`. Текст записи — на английском.
4. В конце цепочки — `Logger.fC_FinishStream_Ch(id)`. Если не вызвать (например, программа упала), при следующем старте поток будет закрыт автоматически как незавершённый.

## Модель данных
- **Реестр потоков** `Straming_path`: `{StreamId: {"name", "started_at", "status": "active"|"finished"}}`.
- **Буфер** `LogBuffer`: `{StreamId: [запись, ...]}` — ещё не записанное на диск.
- **Запись** — всегда 4 поля: `[Время, Код, Значения, Другое]`:
	- Время — `Time.get_ticks_usec()` (микросекунды от старта движка);
	- Код — строка: `"if A and B"`, `"func A(A, B, C)"` и т.п.;
	- Значения — `Array` относящихся к записи переменных;
	- Другое — доп. информация (например, результат `if`) или `null`.

## Файлы на диске
| Путь | Что |
|---|---|
| `res://Save/Logger/Logs/Logger_<роль>_<дата>_<время>.log` | Лог одной сессии: `{"Streams": {StreamId: [запись, ...]}}`. Обёртка `"Streams"` нужна, потому что [[Class_Json]] работает только со словарями |
| `res://Save/Logger/Straming_path.json` | Реестр потоков + `"SessionFile"` (путь к логу текущей сессии). По нему при следующем старте проверяется, всё ли завершилось штатно |
| `res://Save/Logger/Replays/` | Зарезервировано под реплеи (заполнять будет сервер), логгер туда пока ничего не пишет |
| `res://Save/Settings.json` | Отсюда читаются лимиты очистки логов (общий файл настроек, см. [[Сцена Start_Program]]) |

## Переменные (основные)
| Имя | Значение по умолчанию | Смысл |
|---|---|---|
| `FolderLogger` | `res://Save/Logger/Logs/` | Папка логов |
| `FileLogger` | `""` | Лог текущей сессии, назначается при старте |
| `FrequencyUpdates` | `10` | Сколько записей одного потока копится в буфере до автосброса на диск |
| `TimeUpdate` | `1.0` | Сброс по таймеру — **зарезервировано, не подключено** |
| `vGB_LogMaxCountEnabled` / `vGI_LogMaxCount` | `true` / `100` | Лимит числа файлов логов |
| `vGB_LogMaxAgeEnabled` / `vGI_MaxLogAgeDays` | `true` / `30` | Лимит возраста файла, дней |
| `vGB_LogMaxSizeEnabled` / `vGI_MaxLogFolderSizeMb` | `true` / `50` | Лимит объёма папки, МБ |

Лимиты — только значения по умолчанию. Реальные значения читаются из `Settings.json` (ключи `LogMaxCount*`, `LogMaxAge*`, `LogMaxSize*`). Меняются в окне Настроек → «Логи и реплеи» и вступают в силу после перезапуска программы.

## Функции

### Рабочие
- **`fxG_StartingLogger_CrTr(vGS_Role = "user")`** — единая точка старта. По шагам:
	1. Загружает реестр прошлой сессии.
	2. Потоки, оставшиеся `active`, закрывает дописью в **старый** лог (след краша).
	3. Очищает реестр.
	4. Перечитывает лимиты (`fC_LoadLogSettings_Ch`).
	5. Чистит старые логи (`fxG_Resetting_FileLogger_Ch`).
	6. Заводит файл новой сессии и служебный поток `"System"`.
	
	Роль (`"user"`, `"server"`, `"test"`) попадает в имя файла.
- **`fC_RegisterStream_Cr(vCS_Name) -> String`** — новый поток, возвращает `StreamId`. Первая запись потока — факт его создания.
- **`fC_Adding_Buffer_Cr(vCS_StreamId, vCS_Code, vCA_Values, vC_Other = null)`** — добавить запись. При `FrequencyUpdates` записях в буфере потока — автосброс на диск.
- **`fC_FinishStream_Ch(vCS_StreamId)`** — запись о завершении, статус `finished`, сохранение реестра и буфера.
- **`fC_Saving_Logs_Ch()`** — сбросить буфер всех потоков в файл сессии. Файл читается с диска максимум один раз на каждый новый `FileLogger`, дальше накопленное держится в памяти (`_GD_SessionStreamsCache`). Без этого на больших логах было O(n²). Сам файл при каждом сбросе перезаписывается целиком. Вручную вызывать не обязательно, но можно — например, перед рискованной операцией.

### Служебные (вызываются изнутри)
- `_fL_SaveStramingPath_Ch()` — сохранить реестр потоков + `SessionFile`.
- `fC_LoadLogSettings_Ch()` — прочитать лимиты из `Settings.json` (своим экземпляром [[Class_Json]]). Если ключей нет — оставляет значения по умолчанию.
- `fxG_Resetting_FileLogger_Ch()` — удалить старые `*.log`: по возрасту → по количеству → по объёму папки. Каждый шаг работает с тем, что осталось после предыдущего. Выключенный флаг пропускает шаг.

### Задел на будущее (не используется)
Оставлены под будущий автоматический разбор кода вместо ручных `fC_Adding_Buffer_Cr`:
- `fC_OvergrowthIf_Tr` — копия обхода из [[Class_ArrayAndOrDictionary]];
- `PlacesofTextLine(Descriptions, Set)` — позиции подстроки в строке; есть риск зацикливания;
- `New_PathOvergrowth(Parametrs)` — незавершённый парсер строк кода;
- `ReplayReader(...)` — пустая заготовка воспроизведения лога.

## Известные проблемы / не реализовано
- Сброс по таймеру (`TimeUpdate`) не подключён. Теперь, когда логгер — автозагрузка (Node в дереве), это можно сделать через `_process`/`Timer`.
- В `Settings.json` есть лимиты реплеев (`ReplayMax*`), но логгер их не читает: реплеев ещё нет.
- Буфер сбрасывается только по количеству записей. Если программа упадёт, до 9 последних записей каждого потока могут не попасть на диск.
- Имена функций не по [[README]].
