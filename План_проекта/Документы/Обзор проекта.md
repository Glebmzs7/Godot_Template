# Обзор проекта

## О проекте
- **Что это:** Godot_Template — шаблон, общая база кода для Godot-проектов (Life_Operator, Power_struggle). Проекты-потребители получают папку `Сам проект/Godot_Template/` через `git subtree` (см. [[BRANCHES]], [[UPDATING]]).
- **Происхождение:** код начинался внутри проекта Power_struggle. Когда стало понятно, что часть кода нужна и другим проектам, эта часть выделена в самостоятельный шаблон.
- **Название в Godot:** `config/name = "Шаблон (Cluade)"` (`project.godot`).
- **Движок:** Godot 4.7, рендер `gl_compatibility` (и для десктопа, и для мобильных). В `config/features` при этом указано `"Forward Plus"` — см. «Несостыковки».
- **Автор:** Волов Глеб Андреевич (mzs7).
- **Стандарт кода:** [[README]] (версия оформления 0.2.0.1).
- **Смысл:** персональный трекер (чек-листы, дела, здоровье, финансы) с собственным движком построения интерфейса из словарей-конфигов (вместо ручной раскладки нод в редакторе), собственным логированием и клиент-серверным протоколом.

## Карта зависимостей

```
Class_Help            — таблицы типов, вызов callback (FunctionCall)
Class_Json            — чтение/запись JSON
   ↑
Class_ArrayAndOrDictionary — сравнение/обход структур (использует Class_Help, Logger)
Class_Logger (автозагрузка "Logger") — потоки логов (использует Class_Help, Class_Json)
   ↑
Class_UI              — построение и синхронизация нод по конфигу (использует Class_ArrayAndOrDictionary, Logger)
Class_Localization    — переводы (TranslationServer), без зависимостей от шаблона
Class_FileIntegrity   — static-функции отпечатков файлов, без зависимостей

Class_Internet        — общий протокол: конверт, ожидание ответа, повторы, пинг
   ↑ наследуют
Class_InternetClient  — WebSocket-клиент, вход по challenge-response
Class_InternetServer  — TCP/WebSocket-сервер (+TLS), пользователи, токены (использует Class_Json)

Сцены:
Start_Program → Class_UI, Class_Json, Class_Localization, Class_InternetClient, Class_FileIntegrity, Logger
StartServer   → Class_InternetServer, Class_Json, Class_FileIntegrity
TestInterface → Class_UI
TestLogger    → Logger, Class_Json
Home          → (пока ничего)
```

## Запуск и сцены
- **Главная сцена:** `run/main_scene = "uid://h4ph60i1ft80"` — это [[Сцена Start_Program]].
- **Маршрут:** Start_Program (чек-лист из 5 проверок: Logger → Interface → Server → Update → ThirdPartyFiles) → кнопка «Войти» → [[Сцена Home]].
- **Роль "Server":** если в окне выбора аккаунта выбрано техническое значение `"Server"`, программа переключается на [[Сцена StartServer]] и становится локальным сервером `ws://127.0.0.1:9050`. Для проверки клиент+сервер на одном компьютере запускают два экземпляра (в редакторе — «Run Instances»).

## Автозагрузка (autoload)
`Logger = "*res://Godot_Template/Class_Logger.gd"` — один общий экземпляр [[Class_Logger]] на всю программу. Все классы и сцены пишут в лог через глобальное имя `Logger`, поэтому записи всех частей программы попадают в один файл лога сессии (проверяется [[Сцена TestLogger]]).

## Ключевые механизмы (подробности — в документах классов)
- **Интерфейс из конфигов.** Экран описывается вложенным словарём (`__Data_D` / `__Inspector_D` / `__Node_D` + дети), [[Class_UI]] создаёт ноды одним проходом и умеет синхронизировать экран со старого конфига на новый (создать/точечно обновить/пересоздать/удалить только изменившееся). `Class_UI` — обычный объект (`load(...).new()`), поэтому его обязательно добавляют в дерево сцены (`add_child`), иначе не работает `get_tree()`.
- **Логирование потоками.** [[Class_Logger]]: поток — независимая цепочка событий; при старте программы незавершённые потоки прошлой сессии закрываются (след возможного краша), старые логи чистятся по лимитам из `Settings.json`.
- **Сеть.** Один протокол и для сервера игрока (поднимается прямо из клиента), и для будущего глобального сервера (headless-сборка того же кода). Сообщение — конверт `{UserID, Op, Messages, Time, OperationNumber, AnswerTo, AnswerNeeded, Token, ReceivedAt}`. Вход — challenge-response + токен, TLS — опция. Подробно — [[Class_Internet]].
- **Проверки при старте.** Версия программы (`CheckUpdate`) и целостность файлов (`CheckFiles`, [[Class_FileIntegrity]]) сверяются с сервером. Без сервера можно продолжить в автономном режиме — три сетевые проверки тогда помечаются крестиком.
- **Настройки.** `res://Save/Settings.json`: язык, размер окна/полноэкранный режим, масштаб шрифта, громкость, лимиты логов и реплеев, показ окон-подтверждений, защита от автонажатия. Экран настроек — в [[Сцена Start_Program]].

## Несостыковки и известные проблемы (сверено 2026-09-26)
Зафиксировано как есть, код не менялся:
- **Код не соответствует стандарту [[README]] в именах функций.** README 0.2.0.1 требует окончание `_X1X2X3X4` (0/1: создаёт / меняет / удаляет / вызывает функцию). Так названы только 9 функций из ~200: 8 в [[Class_UI]] и 1 в [[Class_ArrayAndOrDictionary]]. Остальные — в старом стиле (`_Cr`, `_Ch`, `_Tr`, `_Bv`…) или без префиксов (`UniversalBypass`, `FunctionCall`, `get_iter_keys`).
- **[[Class_ArrayAndOrDictionary]] передаёт в `Class_Help.FunctionCall` не экземпляр логгера, а сам класс `Class_Logger`** (переменной `Class_Logger` в файле нет, поэтому берётся глобальное имя класса). Пока активный поток пуст (`_vC_ActiveStreamId == ""`), это не срабатывает. Если поток задан — вызов `fC_Adding_Buffer_Cr` на классе, скорее всего, упадёт с ошибкой. Вероятно, должно быть `Logger`. Не проверено запуском.
- **[[Сцена TestInterface]] проверяет исправление, которого в коде нет.** Тест ожидает, что при пересоздании ноды `fC_SyncingNodesWithConfig_1111` восстанавливает её детей через `fC_MassCreatingNode_0001`. В текущем `Class_UI.gd` пересоздание по-прежнему идёт через одиночный `fC_CreatingNode_1000`, дети не создаются заново. При этом тест проверяет только наличие имени в реестре, поэтому, скорее всего, проходит ложно. Возможно, исправление осталось в другой ветке.
- **`fxC_ZoneReplacement` в [[Class_UI]] нерабочая:** `erase()` без аргумента, последняя строка ничего не делает. Нигде не вызывается.
- **`config/features` = "Forward Plus", а рендер — `gl_compatibility`.** Обычно Godot сам пишет сюда текущий рендер. Стоит пересохранить настройки проекта в редакторе.
- **`file_customization/folder_colors` ссылается на `res://Class/`**, а такой папки больше нет — классы в `res://Godot_Template/`.
- **Изменения кода после 24.08 не записаны в changelog-комментарии.** Файлы менялись 11–12.09: переезд в `res://Godot_Template/`, логгер как автозагрузка, сцены `StartServer`/`TestInterface`/`TestLogger`. Записей об этом в `.gd` нет.
- **Пароли аккаунтов на клиенте хранятся открытым текстом** в `res://Save/AccountsList.json` (`{Ник: {"ID", "Password"}}`).
- **Жёстко зашитые значения, которые стоит вынести в настройки** (записано 23.08, в работу не взято): версия программы (`APP_VERSION_S`, `SERVER_LATEST_VERSION_S`), адрес/порт сервера, таймаут подключения и др. Полный список не составлен.
