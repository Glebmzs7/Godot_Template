# Class_UI

Путь: `res://Class/Class_UI.gd`
Наследует: `Node`
Класс: `Class_UI`
Зависит от: [[Class_ArrayAndOrDictionary]] (как `Class_ArrDict`), [[Class_Logger]]

## Для чего нужен
«Движок» построения интерфейса: вместо того чтобы вручную расставлять кнопки/контейнеры в редакторе Godot, экран описывается словарём-конфигурацией (см. также шаблоны нод в `ShablonUI.md` — Control, Label, BaseButton, Button, TextureButton, HBoxContainer, VBoxContainer), а этот класс превращает конфигурацию в реальные ноды сцены, умеет их массово создавать, обновлять и удалять.

## Формат конфигурации ноды
Каждая нода описывается словарём с тремя блоками:
- `__Data_D` — служебные данные: `__type_S` (тип ноды Godot, например `"Button"`), `__Scene_size_V2i` (расчётный размер сцены), `__Path_to_the_node_location_S` (путь до родителя в текущей сцене, куда вставить ноду).
- `__Inspector_D` — свойства, которые обычно выставляются в инспекторе Godot (текст, якоря, отступы, цвет и т.д.) — присваиваются ноде напрямую через `set()`.
- `__Node_D` — сигналы: ключ — имя сигнала ноды (например `"pressed"`), значение — `Callable`, который к нему подключается.

## Функции

### fC_Creating_Node_CrTr(X_NodeConfig_D, A_BelongTo_A)
- Назначение: создать одну ноду по конфигурации и вставить её в текущую сцену.
- Как пользоваться: передать словарь конфигурации в описанном выше формате и массив «тегов принадлежности» (для группировки, см. [[#f__Checking_conditions]]).
- Входные данные: `X_NodeConfig_D: Dictionary` — конфигурация ноды (`__Data_D`/`__Inspector_D`/`__Node_D`); `A_BelongTo_A: Array` — цепочка родительских тегов.
- Выходные данные: `Dictionary` вида `{имя_ноды: {"Node": <нода>, "Scene_size":, "Zero_point":, "name":, "Size":, "A_BelongTo_A":, "__Path_to_the_node_location_S":}}`.
- Принцип работы:
	1. создаёт ноду нужного типа через `ClassDB.instantiate()` (проверяя, что тип вообще существует);
	2. применяет все свойства из `__Inspector_D` (для вложенных словарей — создаёт под-объект через `ClassDB` и заполняет его тоже);
	3. подключает сигналы из `__Node_D`, если они существуют у ноды и `Callable` валиден;
	4. находит контейнер по пути `__Path_to_the_node_location_S` в активной сцене дерева и добавляет туда ноду через `add_child`;
	5. возвращает информацию о созданной ноде.

### fC_Mass_Creating_Node_CrTr(vXD_NodeConfig, vXD_All_nodes)
- Назначение: создать сразу все ноды, описанные во вложенном дереве конфигураций (а не одну).
- Как пользоваться: передать целое дерево конфигураций экрана (как `vXD_BottomPanel_D`/`vXD_TopPanel_D` в `home.gd`) и словарь, куда будут складываться созданные ноды.
- Входные данные: `vXD_NodeConfig: Dictionary` — дерево конфигураций; `vXD_All_nodes: Dictionary` — накопитель созданных нод.
- Выходные данные: нет напрямую — результат копится в `vXD_All_nodes` «по ссылке».
- Принцип работы: запускает обход дерева конфигурации, на каждом узле вызывая [[#f__Checking_conditions]], которая и решает, когда пора создавать ноду через [[#fC_Creating_Node_CrTr]].
- ⚠️ Несостыковка: в коде вызывается `Class_ArrDict.fC_Overgrowth_tree_Tr(...)`, но в [[Class_ArrayAndOrDictionary]] такой функции нет — есть [[Class_ArrayAndOrDictionary#fC_OvergrowthIf_Tr]] с похожим, но другим именем. В текущем виде вызов, скорее всего, приведёт к ошибке.

### f__Checking_conditions(vLS_key, v_D_Holderv2, vLD_func_variable)
- Назначение: callback для обхода дерева конфигурации — на каждом ключе решает, пропустить ли его, создать ли ноду или продолжить спуск глубже.
- Как пользоваться: не вызывается вручную — передаётся как `"func"` внутри [[#fC_Mass_Creating_Node_CrTr]].
- Входные данные: `vLS_key: String` — текущий ключ словаря; `v_D_Holderv2: Dictionary` — значение по этому ключу (потенциальный узел или группа); `vLD_func_variable: Dictionary` — накопленные параметры обхода, включая `"vXD_All_nodes"` и `"A_BelongTo_A"`.
- Выходные данные: `Array` — `[продолжать_обход, продолжать_цикл, идти_глубже]`.
- Принцип работы: служебные ключи (`__Data_D`, `__Inspector_D`, `__Node_D`) пропускаются без углубления; если у текущего узла есть родительский тег `"v__Ebeveyn"`, он добавляется в цепочку `A_BelongTo_A`; если словарь содержит все три обязательных блока — это описание готовой ноды, вызывается [[#fC_Creating_Node_CrTr]], результат добавляется в `vXD_All_nodes`, и дальше вглубь этого узла уже не идём; иначе — считаем узел просто «группой» и разрешаем идти глубже.

### fC_Node_changes_key(vXD_All_nodes, vXA_Array_key, vLS_func, vLD_func_variable)
- Назначение: массово применить функцию ко всем уже созданным нодам, у которых в цепочке тегов (`A_BelongTo_A`) встречается один из указанных ключей.
- Как пользоваться: передать список созданных нод, список тегов-фильтров и callback, который получит на вход саму ноду и должен решить, что с ней сделать.
- Входные данные: `vXD_All_nodes: Dictionary` — все созданные ноды; `vXA_Array_key: Array` — теги, по которым фильтруем; `vLS_func: Callable`; `vLD_func_variable: Dictionary` — дополнительные параметры для callback-а.
- Выходные данные: нет напрямую — эффект достигается через побочные действия внутри `vLS_func`.
- Принцип работы: перебирает все ноды и все теги-фильтры; при совпадении вызывает `vLS_func`; в конце удаляет из `vXD_All_nodes` те записи, которые были помечены на удаление.

### fxG_BatchFillNodeConfig_Cr(vD_BaseTemplate, vD_DiffTemplate, vI_Count)
- Назначение: сгенерировать несколько похожих конфигураций нод из одного шаблона — например, N одинаковых строк списка с разным текстом/номером.
- Как пользоваться: задать общий шаблон (`vD_BaseTemplate`), шаблон различий с плейсхолдером `%N` (`vD_DiffTemplate`, например `{"__name_S": "Item%N", "text": "Пункт %N"}`) и количество копий.
- Входные данные: `vD_BaseTemplate: Dictionary`; `vD_DiffTemplate: Dictionary`; `vI_Count: int`.
- Выходные данные: `Dictionary` — набор уникальных конфигураций, ключ — сгенерированное имя.
- Принцип работы: в цикле `vI_Count` раз клонирует базовый шаблон, подставляет `%N` → номер копии в имени и во всех строковых полях `vD_DiffTemplate`, записывает результат под уникальным именем.

### fxC_UpdateExistingNodes_Ch(vXD_All_nodes, vD_Changes)
- Назначение: изменить свойства уже существующих (созданных ранее) нод.
- Как пользоваться: передать словарь изменений вида `{"ИмяНоды": {"свойство": новое_значение, ...}}`.
- Входные данные: `vXD_All_nodes: Dictionary` — созданные ноды; `vD_Changes: Dictionary` — что и где поменять.
- Выходные данные: нет.
- Принцип работы: для каждой ноды из `vD_Changes` проверяет, что она существует (иначе — предупреждение через [[Class_Logger]]), и для каждого свойства — что оно есть у ноды, затем меняет его через `set()`, логируя результат.

### fxC_SceneSwitching(scene_path)
- Назначение: сменить текущую сцену из любого места кода.
- Как пользоваться: `fxC_SceneSwitching("res://Scenes/UIScenes/Home/Home.tscn")`.
- Входные данные: `scene_path` — путь к файлу сцены.
- Выходные данные: нет.
- Принцип работы: вызывает `change_scene_to_file` отложенно (`call_deferred`) через дерево сцены.
- Связано с: [[Сцена Start_Program]] — вероятный будущий вызов этой функции для перехода со стартового экрана дальше.

### fxC_MassDelitNode(MassOfExistingNodes, RemovalCondition)
- Назначение: удалить ноды, подходящие под условие.
- Как пользоваться: передать все созданные ноды и `Callable`, который на входе получает тег и данные ноды и возвращает `true`/`false` — удалять её или нет.
- Входные данные: `MassOfExistingNodes: Dictionary`; `RemovalCondition: Callable`.
- Выходные данные: нет.
- Принцип работы: перебирает ноды и их теги принадлежности (`A_BelongTo_A`); если условие сработало — помечает ноду на удаление (`queue_free()` + добавление в очередь), затем в конце вычищает их из словаря.
- Используется в: `home.gd` (рабочая зона) — например, там удаляются все ноды с тегом `"TopPanel"` при нажатии на кнопку «Чек листы».

### fxC_ZoneReplacement(Coordinates, Zones, MewZones)
- Назначение (по замыслу): удалить все ноды одной «зоны» и заменить её другой.
- Текущее состояние: не завершена/содержит ошибку — `Coordinates[Zones].erase()` вызван без аргумента (у `Array`/`Dictionary.erase()` он обязателен), а последняя строка `Coordinates[MewZones]` просто читает значение и ничего с ним не делает.
