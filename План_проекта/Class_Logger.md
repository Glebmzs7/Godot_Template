# Class_Logger

Путь: `res://Class/Class_Logger.gd`
Наследует: `Node`
Класс: `Class_Logger`
Версия оформления: 1.0.0.0 (переписан 2026-07-22)
Зависит от: [[Class_Help]], [[Class_Json]]

## Для чего нужен
Система логирования и «перемотки» состояния программы. В отличие от первой версии (сейчас уже не заготовка, а рабочая система) записывает данные о каждой развилке в коде (`if`, вызов функции, присваивание) в независимые **потоки** — не пересекающиеся друг с другом цепочки задач, которые могут выполняться параллельно. Цели: находить ошибки по накопленным данным, восстанавливать позицию в коде, на которой всё пошло не так, и в перспективе — проигрывать (реплеить) ход программы заново.

## Модель данных

### Поток (Stream)
Независимая, не пересекающаяся с другими до своего завершения последовательность событий — например, одна сцена, один сценарий действий пользователя и т.п. Один поток не обязан совпадать «один в один» со скриптом или нодой: скрипт может завести несколько потоков, а несколько скриптов — писать в один и тот же поток.

`Straming_path: Dictionary` — реестр потоков текущей сессии:
```
{
	"0": {"name": "System", "started_at": <тики>, "status": "active" | "finished"},
	"1": {"name": "StartProgram", "started_at": <тики>, "status": "finished"},
	...
}
```

### Буфер
`LogBuffer: Dictionary` — записи, ещё не сброшенные на диск, сгруппированы по тому же `StreamId`:
```
{ "0": [запись, запись, ...], "1": [запись, ...] }
```

### Формат одной записи
`[Время, Код, Значения, Другое]` — всегда 4 поля, неиспользуемые — `null`:
- **Время** — `Time.get_ticks_usec()` на момент записи (монотонное, в микросекундах с начала работы движка)
- **Код** — `String`, что произошло: `"if A and B"`, `"func A(A, B, C)"`, `"A = B.func()"`, `"Поток создан: ..."` и т.п.
- **Значения** — `Array` относящихся к записи переменных
- **Другое** — доп. информация (например, результат `if`), `null`, если не нужна

Примеры: `[12045000, "if A and B", [A, B], true]`, `[12045512, "func A(A, B, C)", [A, B, C], null]`.

## Файлы на диске
- `Save/Logger/Straming_path.json` — реестр потоков + `"SessionFile"` (путь к файлу лога текущей сессии). Перезаписывается при каждом `fC_RegisterStream_Cr`/`fC_FinishStream_Ch`.
- `Save/Logger/Logger_<роль>_<дата>_<время>.log` — файл лога одной сессии (создаётся заново каждый запуск программы), формат: `{"Streams": {StreamId: [запись, запись, ...]}}`. Обёрнут в словарь `"Streams"`, а не голый массив, потому что [[Class_Json]] умеет сохранять/загружать только `Dictionary` — эта обёртка позволяет использовать `Class_Json` без переделки.

## Переменные
- `FolderLogger` — папка с файлами логов, `res://Save/Logger/`
- `FileStraming_path` — путь к реестру потоков, `res://Save/Logger/Straming_path.json`
- `FileLogger` — путь к файлу лога текущей сессии; пустая строка, пока не вызван [[#fxG_StartingLogger_CrTr]]
- `Straming_path` — реестр потоков (см. выше)
- `LogBuffer` — буфер ещё не сохранённых записей (см. выше)
- `vGI_NextStreamId` — счётчик для генерации `StreamId`
- `FrequencyUpdates` — сколько записей в буфере ОДНОГО потока допускается перед автосбросом на диск (по умолчанию 10)
- `TimeUpdate` — интервал сброса по времени; **зарезервирован**, таймер пока не подключён (см. «Открытые вопросы»)
- `vGI_MaxLogAgeDays` — сколько дней хранить файл лога, прежде чем удалить (по умолчанию 14)
- `vGI_MaxLogFolderSizeMb` — предельный суммарный объём папки логов в МБ, прежде чем начнём удалять самые старые файлы (по умолчанию 50)

## Функции

### fxG_StartingLogger_CrTr(vGS_Role = "user")
- Назначение: единая точка входа при запуске программы. Вызывается один раз в самом начале — сейчас это делает [[Сцена Start_Program]].
- Как пользоваться: `Class_Logger.fxG_StartingLogger_CrTr()` (или `fxG_StartingLogger_CrTr("server")`, если сессия серверная).
- Входные данные: `vGS_Role: String` — роль сессии, `"user"` или `"server"`.
- Принцип работы:
	1. Загружает `Straming_path.json` прошлой сессии (если есть) вместе с именем её файла лога (`"SessionFile"`).
	2. Для каждого потока, оставшегося `"active"` (то есть не был завершён штатно — след аварийного закрытия/крэша), дописывает в **старый** файл лога закрывающую запись `"Stream was not finished properly — appended on next startup"` и помечает поток завершённым — так старый лог гарантированно сохраняется целиком, прежде чем его реестр будет очищен.
	3. Только после этого очищает реестр и буфер в памяти.
	4. Удаляет устаревшие файлы логов через [[#fxG_Resetting_FileLogger_Ch]].
	5. Формирует имя нового файла лога (`Logger_<роль>_<год-месяц-день>_<час-минута-секунда>.log`) и регистрирует служебный поток `"System"` через [[#fC_RegisterStream_Cr]] — он живёт всю сессию и в него можно писать системные события логгера.

### fC_RegisterStream_Cr(vCS_Name)
- Назначение: регистрирует новый поток.
- Как пользоваться: `var id = Class_Logger.fC_RegisterStream_Cr("StartProgram")` — дальше этот `id` передаётся во все записи этого потока.
- Входные данные: `vCS_Name: String` — понятное имя потока.
- Выходные данные: `String` — `StreamId`.
- Принцип работы: генерирует id (`vGI_NextStreamId`, инкремент), заводит запись в `Straming_path` со статусом `"active"`, заводит пустой буфер, первой же записью в буфер пишет `"Stream created: <имя>"` через [[#fC_Adding_Buffer_Cr]], сохраняет реестр на диск через [[#_fL_SaveStramingPath_Ch]].

### fC_FinishStream_Ch(vCS_StreamId)
- Назначение: корректно завершает поток.
- Как пользоваться: `Class_Logger.fC_FinishStream_Ch(id)`, когда поток закончил свою работу (сцена закрывается, задача выполнена и т.п.).
- Принцип работы: пишет в буфер потока запись `"Stream finished: <имя>"` (последней записью потока), меняет статус на `"finished"`, сохраняет реестр, затем сохраняет буфер на диск через [[#fC_Saving_Logs_Ch]].

### fC_Adding_Buffer_Cr(vCS_StreamId, vCS_Code, vCA_Values, vC_Other = null)
- Назначение: добавляет одну запись в буфer указанного потока — это и есть тот самый «явный вызов в месте развилки», о котором договорились (без автоматического парсинга кода).
- Как пользоваться: `Class_Logger.fC_Adding_Buffer_Cr(id, "if A and B", [A, B], result)`.
- Принцип работы: собирает запись `[Время, Код, Значения, Другое]`, кладёт в `LogBuffer[StreamId]`; если размер буфера этого потока достиг `FrequencyUpdates` — сразу вызывает [[#fC_Saving_Logs_Ch]] (автосброс по количеству записей).

### fC_Saving_Logs_Ch()
- Назначение: сбрасывает буфер всех потоков в файл лога текущей сессии.
- Принцип работы: подгружает уже накопленное в `FileLogger` (если файл уже существует) через [[Class_Json#fxG_LoadJson_Cr]], дописывает к каждому потоку новые записи, сохраняет обратно одним словарём `{"Streams": {...}}` через [[Class_Json#fxG_SaveJson_Ch]], очищает буфер в памяти.

### _fL_SaveStramingPath_Ch()
- Назначение: служебная — сохраняет текущий `Straming_path` вместе с именем файла сессии (`"SessionFile"`) в `Straming_path.json`, чтобы при следующем запуске можно было проверить, всё ли было завершено штатно.
- Вызывается автоматически из [[#fC_RegisterStream_Cr]] и [[#fC_FinishStream_Ch]] — вручную дёргать не нужно.

### fxG_Resetting_FileLogger_Ch()
- Назначение: удаляет устаревшие файлы логов в `FolderLogger`.
- Принцип работы: собирает список `*.log` файлов с датой изменения и размером; сначала удаляет всё старше `vGI_MaxLogAgeDays`; если оставшееся всё ещё превышает `vGI_MaxLogFolderSizeMb` суммарно — удаляет самые старые файлы по очереди, пока не впишемся в лимit.

## Оставлено без изменений (задел на будущее)
Ниже — то, что решили пока не трогать, чтобы позже можно было добавить автоматический разбор кода вместо ручных вызовов [[#fC_Adding_Buffer_Cr]]:
- `PlacesofTextLine` — поиск позиций подстроки в строке (⚠️ есть риск зацикливания, см. описание в прошлой версии документа)
- `fC_OvergrowthIf_Tr` — обход словаря с callback (та же логика, что в [[Class_ArrayAndOrDictionary#fC_OvergrowthIf_Tr]])
- `New_PathOvergrowth`, `New_Path` — незавершённый парсер строк кода (в `New_Path` есть синтаксически некорректные строки — не компилируется как есть)
- `ReplayReader` — пустая заготовка воспроизведения записанного лога

## Открытые вопросы / что не реализовано
- **Сброс по таймеру.** `TimeUpdate` объявлена, но не подключена: `Class_Logger` создаётся как обычный объект (`load(...).new()`), не добавляется в дерево сцены — значит, `_process`/`Timer` у него не будет тикать сам по себе. Чтобы включить сброс по времени, нужно либо добавлять `Class_Logger` в дерево (как сейчас сделано с `Class_UI` в [[Сцена Start_Program]]), либо вызывать проверку вручную из чужого `_process`.
- **Настройки очистки логов не вынесены в `Settings.json`.** `vGI_MaxLogAgeDays`/`vGI_MaxLogFolderSizeMb` — пока просто значения по умолчанию в коде.
- **`Class_UI.fxC_UpdateExistingNodes_Ch` вызывает `Class_Logger.fx__Log_Warn`/`fx__Log_Info`** — таких функций в `Class_Logger` по-прежнему нет (не входило в эту переработку, отдельно зафиксировано в [[Обзор проекта]]).
- **Формат на диске обёрнут в `{"Streams": {...}}`** (словарь по `StreamId`), а не хранится как «голый» вложенный массив потоков, как в самом первом примере формата, который предлагался при обсуждении — решение принято ради переиспользования [[Class_Json]] без его переделки.
