# Обзор проекта

## О проекте
- Название: «Шаблон (Cluade)» (внутреннее кодовое имя из README — Power_struggle)
- Движок: Godot 4.7, рендер `gl_compatibility`
- Автор: Волов Глеб Андреевич (mzs7)
- Разрешение окна: 540×900 (viewport), расчётный размер генерируемых сцен UI — 1080×1920 (`vSV2_Scene_size_V2i`)
- Смысл проекта: персональный трекер (чек-листы, дела, здоровье, финансы) с самодельным движком построения интерфейса из словарей-конфигураций, вместо ручной раскладки нод в редакторе Godot, и собственной системой логирования/реплея.

## Система шаблонов UI
Экраны не собираются вручную в редакторе, а описываются словарём конфигурации и превращаются в реальные ноды через [[Class_UI#fC_Creating_Node_CrTr]] и [[Class_UI#fC_Mass_Creating_Node_CrTr]]. Готовые «заготовки» типовых нод (Control, Label, BaseButton, Button, TextureButton, HBoxContainer, VBoxContainer) с расписанными полями инспектора и пояснениями к каждому полю лежат в файле `ShablonUI.md` в корне проекта.

**Важно для использования [[Class_UI]] в принципе:** он создаётся как обычный объект через `load(...).new()` и по умолчанию не находится в дереве сцены. Функции, которым нужен `get_tree()` (например, [[Class_UI#fxC_SceneSwitching]]), без явного `add_child(Class_UI)` где-нибудь в живой сцене работать не будут — это и есть причина, почему `fxC_SceneSwitching` не был рабочим до правок в [[Сцена Start_Program]].

## Система логирования
[[Class_Logger]] переписан с нуля (2026-07-22): потоки — независимые непересекающиеся цепочки событий, хранятся словарём; каждый поток при регистрации/завершении сам пишет об этом запись в свой лог; единая функция [[Class_Logger#fxG_StartingLogger_CrTr]] при старте программы проверяет, что лог прошлой сессии сохранён целиком (дозаписывает незавершённые потоки как след возможного крэша), чистит устаревшие файлы логов и заводит файл новой сессии. Подробности, формат данных и открытые вопросы — в [[Class_Logger]].

## Сетевая архитектура (план, обновлено 2026-08-23)
Решено делать обмен с сервером в виде сообщений «операция + время → ответ/изменения + время», один и тот же протокол — что для сервера, который поднимает у себя игрок (прямо внутри клиентского процесса, «host and play»), что для официального глобального сервера (headless-сборка того же кода). Из-за требования «сервер поднимается прямо из клиента» решили не заводить отдельный технологический стек/проект под сервер — GDScript, три новых класса вместо двух: [[Class_Internet]] (родитель — общие для обеих сторон `SendingMessage`/`WaitingResponse`) и его наследники [[Class_InternetClient]]/[[Class_InternetServer]] (каждый — своя `EstablishingConnection`/`ReceivingNotification`, то, что у клиента и сервера действительно разное). Формат сообщения, адресация, расчёт пинга/синхронизации времени, авторизация (токен после входа + challenge-response, без TLS на этом этапе) и весь список открытых вопросов — в [[Class_Internet]] (общее) и по каждому наследнику отдельно. Первый черновик кода написан и отправлен пользователю на ревью (2026-08-22), затем протокол доработан по итогам разбора (2026-08-23) и переписанный код (`Class_Internet.gd`, `Class_InternetClient.gd`, `Class_InternetServer.gd`) записан на диск в тот же день — реального подключения к сцене пока нет (см. следующий абзац, `_fC_RunServerCheck_Ch` — заглушка).

Отдельно (2026-08-23, правлено дважды в тот же день): на стартовом экране ([[Сцена Start_Program]]) при доходе до проверки «Соединение с сервером» (ключ `"Server"` в `vLA_CheckOrder_A`) добавляется окно-выбор аккаунта. По обратной связи ("окно должно спрашивать под проверками в отведённом окошке") окно больше НЕ полноэкранный оверлей — живёт прямо внутри уже существующего `InfoBoxPanel` (того самого "окошка под проверками", где обычно статусный текст чек-листа). Список аккаунтов больше не хардкод — читается из `res://Save/AccountsList.json` (`{Ник: {"ID","Password"}}`, заводится с одним примером `"Пользователь1"` при первом запуске) и показан в `ScrollContainer` ("аккаунтов может быть много" — прокрутка вместо переполнения небольшой панели), в конце списка всегда есть кнопка «+» — открывает форму добавления аккаунта (Ник/ID/Пароль), после сохранения список кнопок обновляется на лету через `Class_UI.fC_SyncNodesWithConfig_Ch` (без перезапуска программы). Плюс техническое значение `"Server"` — чтобы на одном устройстве можно было одновременно эмулировать и сервер (выбрав `"Server"`), и клиента (выбрав реальный аккаунт), запустив два экземпляра программы (в редакторе Godot — кнопка «Run Instances»/«Customize Run Instances» рядом с Play). Подробности — [[Сцена Start_Program]].

Отдельно найден и починен баг (2026-08-23, не связан с окном аккаунтов): попап «изменения (Логи и реплеи) применятся после перезапуска» вылезал при каждом запуске программы даже без захода в настройки — причина в том, что программная синхронизация чекбоксов с сохранёнными настройками (`_fC_UpdateLoggerCheckVisual_Ch`/`_fC_UpdateConfirmToggleVisual_Ch`) присваивала `button_pressed` напрямую, а это само по себе испускает сигнал `"toggled"` в Godot при реальном изменении значения — заменено на `set_pressed_no_signal()`. Подробности — [[Сцена Start_Program]].

Дальше (2026-08-23, фаза 1 РЕАЛИЗОВАНА): проверка `"Server"` в чек-листе
[[Сцена Start_Program]] теперь настоящая, не заглушка — реальное подключение
через [[Class_InternetClient]] (реальный аккаунт) или переключение сцены на
`test`, где поднимается [[Class_InternetServer]] (выбор "Server"); при
неудачном подключении дольше 8 секунд предлагается кнопка "Продолжить без
сервера" (автономный режим, теперь отмечает три проверки крестиком, а не
галочкой — см. правку ниже).

И сразу следом (2026-08-23, фаза 2 РЕАЛИЗОВАНА): проверки `"Update"` (сверка
версии программы с сервером) и `"ThirdPartyFiles"` (целостность файлов по
размеру + сэмплам байт) теперь тоже настоящие, а не автопройденные вместе с
"Server". Новый класс [[Class_FileIntegrity]] строит отпечатки файлов
(размер + первый/последний/случайный байт) и на клиенте (что слать), и на
сервере (manifest + проверка присланного); клиент/сервер держатся как
обычное поле, а не через наследование, поэтому обмен "прикладными" (не
транспортными) сообщениями пошёл через новый сигнал `AppOpReceived_S` в
[[Class_Internet]] — заменил TODO-заглушки на месте, где раньше стояло "эти
операции появятся позже". Подробности, формат протокола, manifest и
открытые вопросы (переключатель "выключить проверку совсем", хранение
версии) — [[Class_Internet]] → «После установления соединения: проверки
Update/ThirdPartyFiles».

Также правка по обратной связи ("если подключаемся без сети — то все
крестики", "сколько раз мы пытаемся подключиться?"): автономный режим
раньше отмечал "Server"/"Update"/"ThirdPartyFiles" галочками — теперь
крестиками (честнее — "не проверено", а не "проверено и всё ок"), кнопка
"Войти" (переименована 2026-08-24, была "Властвовать") всё равно появляется через отдельное исключение в
`_fC_UpdateOverallProgress_Ch`. Ответ на "сколько раз" — сейчас РОВНО одна
попытка подключения, `SERVER_CONNECT_TIMEOUT_SECONDS_F` лишь ограничивает,
сколько ЖДАТЬ её результата. Подробности — [[Сцена Start_Program]].

## План: вынести захардкоженные значения в настройки (2026-08-23, записано, в работу не взято)
Обратная связь: в коде разбросано много значений, которые по-хорошему должны
быть настройками, доступными пользователю для изменения, а не константами/
литералами в `.gd`-файлах (например: версия программы для проверки

но идея шире — касается вообще любых "пользовательских" параметров, зашитых
в код, а не в `Settings.json`/UI настроек). Явно отложено пользователем на
следующую итерацию ("мы работает не над этим, если это займёт много времени
просто добавь что это надо сделать в план проекта") — конкретный список
значений, которые стоит перенести, ещё не составлен.
