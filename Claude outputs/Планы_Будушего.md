## Известное ограничение среды: чат Cowork vs Claude Code

- **Claude Code (CLI)** — исполняется как процесс прямо на ПК пользователя, имеет родной
  инструмент `Bash`, который просто запускает Git Bash локально.
- **Cowork (этот чат)** — исполняется в облачном контейнере, к ПК подключается только через
  файловый мост (`remote-devices`). Инструмент `device_bash` в этой сессии отсутствует как
  инструмент вовсе — нет и способа переименовывать/удалять папки и файлы напрямую (только читать
  и (пере)записывать содержимое файлов). git-операции и переименование/удаление файлов
  выполняются пользователем по присланным командным блокам или руками в Проводнике — это
  архитектурное ограничение, не временное.

## Важная находка: хардлинки в папках Yandex Disk ломают запись через файловый мост

`device_commit_files` рапортует `"written"` без ошибок, но `device_stage_files` на этих же файлах
СРАЗУ после этого отказывает с `"file is hardlinked (nlink > 1)"` — побайтовую сверку через мост
сделать невозможно. Похоже, это механизм самого Yandex Disk (облачные плейсхолдеры/дедупликация).
**Практический вывод:** проверка после записи теперь идёт через сравнение размера файла
(`device_list_dir`) — работает надёжно, в отличие от побайтовой сверки через `device_stage_files`.

## Решено / выполнено

- **Главная находка сессии 21.09 — три независимые причины "бесконечного цикла" у Life_Operator и
  Godot_Template, все три найдены и исправлены:**
  1. `config.json` у Life_Operator указывал `path` на `...\Life_Operator\Сам проект`, где
     обнаружился СВОЙ отдельный устаревший `.git`, рассинхронизированный с реальным GitHub
     (настоящий репозиторий — на уровень выше). Путь исправлен на верхний уровень (как у
     Godot_Template).
  2. После включения слежения за ВСЕЙ папкой проекта слежение подхватывало и папку `.git` самого
     репозитория — `git fetch` сам меняет свои служебные файлы (`FETCH_HEAD`), что засчитывалось
     как "материал для пуша" и вызывало новый `git fetch`, бесконечно (несколько циклов в
     секунду).
  3. По той же причине — папка `.autosync_data` (наши же данные репозитория, `repo_data.py`):
     каждое принятие версии обновляет файл там, что при слежении за всей папкой снова
     засчитывалось как "материал для пуша" — самоподдерживающийся цикл РЕАЛЬНЫХ пушей с растущим
     номером версии (обнаружено на Godot_Template).
  Исправлено разом: `.git` и `.autosync_data` — обязательные записи в новом `_ignored_folders()`
  (`watcher.py`), плюс настраиваемый список `config.json → "ignored_folders"` для остального
  (`.godot`, `__pycache__` — заданы по умолчанию). Диагностика велась через новый лог реальных
  git-команд в журнале программы — без него причина 3 осталась бы незамеченной.
- **Сессия 22.09 — найдена и исправлена четвёртая причина "версия не принимается" (Life_Operator):**
  рабочая копия на диске была физически переключена на ветку `main`, а не на `alpha/Mzs7`, за
  которой следит AutoSync — `git commit` коммитил на текущую (`main`), а пуш/тег на `alpha/Mzs7`
  проходили как no-op. Добавлена проверка текущей ветки перед коммитом; по просьбе пользователя
  доработана до автоматического `git checkout` на нужную ветку (вместо остановки с инструкцией).

  на новой ветке (иначе `.autosync_data` может проскочить в коммит) — вынесено в переиспользуемый
