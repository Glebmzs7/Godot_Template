# Обзор проекта — AutoSync

Демон автоматической git-синхронизации: следит за указанными папками внутри git-репозиториев,
сам коммитит и пушит изменения при сохранении файла, и ведёт собственную схему версий-тегов.
Работает через окно (tkinter), без консоли — `Сам проект/AutoSync.pyw`.

## Модули (`Сам проект/`)

- **watcher.py** — ядро. `RepoWatcher.sverka_versiy(reason)` — единая точка входа для всех
  проверок синхронизации (полная логика решений расписана в докстринге файла). Управляет
  слежением (watchdog), периодическими проверками, кнопкой работает/ожидает/остановлена,
  запуском самообновления при старте.
- **gui.py** — окно `AutoSyncGUI`: список репозиториев (по строке на каждый), лог событий,
  диалоги вопросов пользователю (используются и `RepoWatcher`, и не блокируют друг друга).
- **git_ops.py** — тонкая обёртка над командами git (fetch, push, tag, diff, merge и т.п.).
  Не содержит своей логики слияния — использует стандартный `git`/`git mergetool`.
- **version.py** — версия репозитория = свободный текстовый префикс (разработчик задаёт сам)
  + число пушей после запятой (считает только демон). Никакой проверки формата — специально,
  чтобы старые/нестандартные теги не роняли программу.
- **notifier.py** — типы выбора при расхождении версий (`SyncChoice`).
- **state.py** — последняя подтверждённая версия каждого репозитория (`state.json`, не в git).
- **self_update.py** — самообновление САМОГО AutoSync (не игровых репозиториев). Отдельная
  логика — ЗАПУСК_САМОЙ_ПРОГРАММЫ, полностью независима от `RepoWatcher`. Ветка для сверки —
  `update_branch.txt` (не в git), по умолчанию `Stable`.

## Конфигурация (не в git — своя у каждой копии/машины)

- `config.json` — какие репозитории следить, с какой веткой, с каким интервалом проверки
  (шаблон — `config.example.json`).
- `state.json` — известные версии репозиториев.
- `update_branch.txt` — источник самообновления самого AutoSync.

## Две копии программы

- **Рабочая** — используется каждый день для слежения за реальными Godot-проектами (Godot_Template,
  Life_Operator, Power_struggle). Отслеживает ветку `Stable`.
- **Для разработки** — здесь пишется и тестируется новый код. Отслеживает ветку `alpha/Mzs7`,
  использует отдельный тестовый git-репозиторий вместо реальных проектов (чтобы не было двух
  активных слежений за одними и теми же файлами).

Подробнее про ветки — см. `BRANCHES.md` в корне репозитория.
