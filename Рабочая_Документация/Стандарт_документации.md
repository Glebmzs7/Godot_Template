# Стандарт ведения рабочей документации

**Версия: 0.0.1** (версионирование — по аналогии с подходом Стаб-Бета-Альфа: номер растёт при
изменении правил этого файла; дата последнего изменения версии указывается в заголовке раздела
"История версий" в конце).

Это одновременно и стандарт, и навигация по нему — разделов "где что лежит" отдельным файлом нет,
всё в одном месте.

## 1. Назначение

Единый стандарт того, как на всех трёх уровнях координации (Оператор Claude / Оператор отрасли /
Проект) хранятся рабочие документы проекта и автоматическая история их изменений ("Фиксация").
Действует для всех отраслей и проектов без исключения.

## 2. Что есть на каждом уровне

- **Оператор Claude** (`Проекты\Claude\`) и **Оператор отрасли** (например `Проекты\IT\Claude\`) —
  только папка `Фиксация\` (раздел 4 ниже), прямо внутри `Claude\`. Разделения на "рабочие
  документы" им не требуется — на этих уровнях и так всё рабочее.
- **Проект** — папка `Рабочая_Документация\` лежит **в папке самого проекта** (там же, где код/
  материалы проекта), а не в `<Отрасль>\Claude\<Проект>\` — это файлы проекта, не координации
  чатов. Папка `<Отрасль>\Claude\<Проект>\` остаётся отдельно — там сообщения между чатами
  (Вопрос/Ответ/Предложение/Уведомление), с рабочей документацией не смешивается.

## 3. Структура `Рабочая_Документация\` (уровень проекта)

```
Рабочая_Документация\
   Обзор.md                 — живой документ, правится вручную/чатом по мере работы
   Требования\               — требования к проекту (может быть пустой — файл-заглушка внутри)
   Планы_на_будущее.md       — живой список отложенных идей и планов по этому проекту
   Фиксация\
      Изменения\             — см. раздел 4
      Обзоры\                 — см. раздел 4
   Стандарт_документации.md  — полная копия этого файла (раздел 6)
```

## 4. Папка `Фиксация\`

Авто-генерируется ночной задачей ("Ночной обзор IT" и её аналоги для будущих отраслей). Две
подпапки:

- **`Изменения\`** — что добавлено/удалено/изменено в документах этого уровня по сравнению с
  предыдущим файлом фиксации.
- **`Обзоры\`** — снимок состояния на момент проверки, по структуре: Цель проекта / План проекта /
  Актуальные задачи / Что готово.

Это вспомогательная, автоматическая история — не заменяет живой `Обзор.md` в
`Рабочая_Документация\`, который ведётся вручную/чатом в реальном времени.

## 5. Имя файла фиксации

Единая точка отсчёта ("День 0") для всей системы — **09.10.2026**, одна и та же на всех уровнях
и во всех отраслях/проектах, текущих и будущих.

Имя файла — `<N>.md`, где `N` — целое число полных календарных суток от Дня 0 (сегодня = 0,
завтра = 1, и так далее). Без суффиксов `-2`/`-3` — ночная задача пишет не чаще одного файла в
сутки в каждую из двух подпапок, коллизий по логике быть не может.

## 6. Полная копия стандарта в каждом проекте

В `Рабочая_Документация\` каждого проекта лежит **полная копия** этого файла (не ссылка и не
краткая пометка о версии). Это позволяет увидеть, какой версии стандарта проект фактически
следует, даже если центральный файл (`Проекты\Claude\Документация\Стандарт_документации.md`)
уже обновился, а копия в проекте — ещё нет. При обновлении центрального файла копии в проектах
обновляются отдельно, не автоматически.
