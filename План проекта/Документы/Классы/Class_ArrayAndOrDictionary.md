# Class_ArrayAndOrDictionary

## Назначение
Сравнение, слияние и обход массивов и словарей любой глубины вложенности. Главное применение — «движок сравнения» для [[Class_UI]]: по результату сравнения старого и нового конфига экрана `Class_UI` решает, какие ноды создать, обновить, пересоздать или удалить. Универсальный обход `UniversalBypass` используется в `Class_UI` для построения экрана.

## Как подключать
`var vCC_ClassArrDict = load("res://Godot_Template/Class_ArrayAndOrDictionary.gd").new()` (так делает [[Class_UI]]). Внутри создаёт свой экземпляр [[Class_Help]].

## Логирование
`_vC_ActiveStreamId: String` — id потока [[Class_Logger]], куда писать ход обхода и сравнения. Выставляется **снаружи** перед вызовом (класс сам потоки не регистрирует). Записи идут через автозагрузку `Logger`, но только когда `_vC_ActiveStreamId != ""`. [[Class_UI]] пишет свои записи в этот же поток.

## Функции

### Сравнение массивов
- **`fL_CompareArrays_Tr(array1, array2) -> bool`** — полное совпадение: та же длина, те же элементы в том же порядке.
- **`fL_CompareArraysUnordered_Tr(array1, array2) -> bool`** — совпадение без учёта порядка (сравнивает частоты элементов).

### Слияние словарей
- **`fG_MergeDictionariesRecursive_Cr(Dict1, Dict2) -> Dictionary`** — глубокое слияние, приоритет у `Dict2`. `Dict1` не меняется (работа идёт с глубокой копией). Вложенные словари сливаются рекурсивно, остальное заменяется значением из `Dict2`.
- **`fxL_MergeCallback_Tr(vLS_Key, v_, vLD_External) -> Array`** — callback слияния для обхода: `vLD_External = {"Target_D", "Source_D"}`, возвращает `[[Bv_Continue, Bv_ContinueFor, Bv_GoDeeper], v_ChildValue]`.

### Обход структур
- **`UniversalBypass(variables, funcparametrs, PathArray = [], Depth = 0)`** — главный обход любой вложенной структуры. На каждом ключе вызывает callback из `funcparametrs` через `Class_Help.FunctionCall`. Callback получает `[свои Parametrs..., type_id, текущий уровень, PathArray, ключ]` и возвращает команду:
	- `"Deeper"` — зайти внутрь значения (если оно контейнер);
	- `"Further"` — перейти к следующему ключу на этом уровне;
	- `"Higher"` — прекратить обход этого уровня и вернуться наверх.
	
	`PathArray` — общий путь от корня до текущего ключа, поддерживается самим обходом. Защита от бесконечной рекурсии: при `Depth > 40` обход останавливается с `push_error` и записью в лог (без падения программы).
- **`PassageAlongWay(Variables1, PathArray, FuncParametrs = {})`** — пройти по структуре по цепочке ключей и вернуть найденное значение. Работает с глубокой копией. С `FuncParametrs` перед каждым шагом спрашивает callback, заходить ли по ключу: так пропускаются служебные `"Child"`, см. `_PAW_CO2V`.
- **`fC_OvergrowthIf_Tr(vLD_FirstVariable, vLS_func, PathArray = [])`** — старый рекурсивный обход словаря с флагами управления. В текущем коде вместо него используется `UniversalBypass`. Копия этой функции есть в [[Class_Logger]].
- **`CheckingPath(PathArray, FuncParametrs, Variables)`** — **не используется** с 13.08 (заменена на `RecalculateResultsRecursive`), оставлена в файле.

### Глубокое сравнение двух значений
- **`fC_ComparisonsOf2Variables_0101(Variables1, Variables2, ReturnDictionary)`** — главная точка входа. Сравнивает два любых значения. Если оба — контейнеры и они не равны, сравнивает содержимое рекурсивно. Результат записывается в переданный `ReturnDictionary`:
	```
	{"result": "код", "Values": [Variables1, Variables2], "Child": {ключ: {тот же формат}, ...}}
	```
	`"Child"` есть, только если сравнение ушло на уровень ниже.
- **Коды результата:**
	| Код | Значение |
	|---|---|
	| `+` | полностью совпадают |
	| `-` | различаются (не контейнеры или разные типы) |
	| `>` | ключ/элемент есть только в первом значении |
	| `<` | только во втором |
	| `~` | оба контейнеры, внутри есть различия (детали в `Child`) |
	| `~-`, `~>`, `~<`, `~>-`, `~<-` | агрегированный итог узла по кодам его детей (есть совпадающие и различающиеся / добавленные / удалённые ключи) |
	| суффикс `KM` | «keys match»: ключ присутствует в обоих значениях (`+KM`, `-KM`, `~KM`…). Узел, собранный только из непересекающихся ключей (`>`/`<`), `KM` не получает |
- Внутренние функции сравнения (напрямую не вызываются):
	- `_C_ComparisonsOf2Variables_0101(InputArray)` — callback для `UniversalBypass`, досравнивает значения на каждом уровне, возвращает `"Deeper"`/`"Further"`;
	- `RecalculateResultsRecursive(Node)` — после обхода пересчитывает итоговые коды снизу вверх (сначала дети, потом родитель);
	- `_CP_CO2V(Variables)` — считает итоговый код одного узла по кодам детей;
	- `_PAW_CO2V(Array)` — callback для `PassageAlongWay`, пропускает служебный ключ `"Child"`.

## Известные проблемы
- **Передаёт в `Class_Help.FunctionCall` класс `Class_Logger`, а не экземпляр `Logger`** (переменной `Class_Logger` в файле нет). Пока `_vC_ActiveStreamId` пуст — не срабатывает. Если поток задан, вызов логирования внутри `FunctionCall`, скорее всего, упадёт. Не проверено запуском.
- **Логическая ошибка в ветке `"Child"`** (найдена 09.08, не решена): тест `{"x":1}` против `{"x":2}` давал `"~"` с пустым `Child.x` вместо ожидаемого `"-"`. С 13.08 пересчёт итогов переписан (`RecalculateResultsRecursive`), повторной проверки этого случая в документах нет.
- Отладочный компромисс от 14.08: логирование сравнения задумывалось всегда включённым. Сейчас в коде стоят условия `if _vC_ActiveStreamId != ""` — стоит уточнить, какое поведение актуально.
- Неиспользуемые `CheckingPath`, `fC_OvergrowthIf_Tr` — кандидаты на удаление.
- Имена функций в основном не по [[README]] (единственная по стандарту — `fC_ComparisonsOf2Variables_0101`).
