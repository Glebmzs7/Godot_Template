# Как обновить общий код шаблона в проекте-потребителе

Эта папка (`Godot_Template/`) приходит в проект как `git subtree` из репозитория `Godot_Template`
(remote `godot-template`). Полную политику веток (что такое `Stable`/`Beta`/`alpha/*`) см. в
`BRANCHES.md` в корне репозитория шаблона — здесь только команды для потребителя.

⚠️ **`Godot_Template/` не редактируется напрямую.** Если нужно изменить поведение шаблонного
класса под этот проект — заведите/дополните `Godot_Template_<ИмяЭтогоПроекта>/` рядом (классы,
наследующие/переопределяющие шаблонные) и работайте там. См. раздел «Слой кастомизации» ниже.

⚠️ **`git subtree split` и `git subtree push` не работают, если путь до папки у вас содержит
пробел** (например `Сам проект/Godot_Template`, как в Life_Operator) — падает с
`fatal: assertion failed`, известный баг git-subtree. Если у вас путь без пробела (например
просто `Godot_Template`, как в Power_struggle) — обычный `git subtree push` работает нормально,
это ограничение только `split`. Если путь с пробелом — используйте ручной вариант через
plumbing-команды (см. «Отправить правки обратно» ниже) и для `split` (см. «Обновление общего
кода»), и для push.

## Разовая настройка (уже сделана в этом проекте)

```bash
git remote add godot-template <путь-или-URL-к-Godot_Template>
git fetch godot-template export/Stable
git subtree add --prefix=Godot_Template godot-template export/Stable --squash
```

## Обновление общего кода (подтянуть новое из шаблона)

По умолчанию тянем `export/Stable` — то, что уже прошло обкатку в `Beta`. Если нужен ранний
доступ к тому, что ещё обкатывается — `export/Beta` вместо `export/Stable` везде ниже.

```bash
git fetch godot-template export/Stable
git subtree pull --prefix=Godot_Template godot-template export/Stable --squash
```

Новый файл, добавленный в `Godot_Template/` шаблона, подхватывается тем же `subtree pull` —
отдельных шагов не требует.

После pull — сверьтесь с `Godot_Template_<ИмяЭтогоПроекта>/`: если что-то из переопределённого
там теперь один в один реализовано и в обновлённом `Godot_Template/`, переопределение можно
убрать и переключить обращения в коде проекта на `Godot_Template` напрямую (см. раздел ниже).

(Для того, кто ведёт сам шаблон: обновить `export/Stable`/`export/Beta` после правок на
соответствующей полной ветке — вручную, `subtree split` не работает:
```bash
TREE=$(git rev-parse "Stable:Сам проект/Godot_Template")
NEWCOMMIT=$(git commit-tree "$TREE" -m "Godot_Template/ из ветки Stable" -p export/Stable)
git branch -f export/Stable "$NEWCOMMIT"
git push origin export/Stable --force
```
то же самое для `Beta`/`export/Beta`.)

## Слой кастомизации: Godot_Template_\<ИмяЭтогоПроекта\>/

Код, специфичный для этого проекта, но логически связанный с шаблонными классами (например,
переопределение поведения `Class_Logger` под нужды именно этого проекта), не пишется прямо в
`Godot_Template/` — он живёт в соседней папке `Godot_Template_<ИмяЭтогоПроекта>/`: классы,
которые наследуют шаблонные (`extends Class_Logger` и т.п.) и переопределяют/дополняют нужные
части. Остальной код проекта обращается к этим переопределениям, а не напрямую к `Godot_Template`,
там где переопределение существует.

Правки в этом слое, которые имеет смысл предложить всем проектам — отправляются в `alpha/<Имя
ЭтогоПроекта>` в репозитории шаблона (см. «Отправить правки обратно» ниже), по отдельности на
каждый класс/метод, а не одним общим коммитом — чтобы ведущий шаблона мог разобрать их по
пунктам.

## Отправить правки обратно в шаблон

Если, работая в этом проекте, вы поправили что-то в `Godot_Template_<ИмяЭтогоПроекта>/` и хотите
предложить это шаблону — отправьте изменения в приёмную ветку `alpha/<ИмяЭтогоПроекта>` в
репозитории шаблона:

Путь без пробела (например `Godot_Template`, как в Power_struggle) — обычный subtree push:
```bash
git subtree push --prefix=Godot_Template godot-template alpha/<ИмяЭтогоПроекта>
```

Путь с пробелом (например `Сам проект/Godot_Template`, как в Life_Operator) — `subtree push`
падает с тем же багом, что и `split` (см. предупреждение выше), поэтому вручную:
```bash
git fetch godot-template alpha/<ИмяЭтогоПроекта>
TREE=$(git rev-parse "HEAD:Сам проект/Godot_Template")
NEWCOMMIT=$(git commit-tree "$TREE" -m "Godot_Template/ из <ИмяЭтогоПроекта>" -p FETCH_HEAD)
git push godot-template "$NEWCOMMIT":alpha/<ИмяЭтогоПроекта>
```

`<ИмяЭтогоПроекта>` — `Life_Operator` или `Power_struggle`, приёмная ветка
`alpha/<ИмяЭтогоПроекта>` в репозитории `Godot_Template`. Дальше это на усмотрение того, кто
ведёт шаблон: посмотреть, вручную влить удачное в `Beta` (а оттуда со временем в `Stable`) — не
автоматика.

## Если нужно править общий код прямо здесь

Можно — subtree это обычные файлы, `git` не запрещает их менять напрямую в `Godot_Template/`.
При следующем `subtree pull` могут возникнуть обычные конфликты слияния для изменённых файлов —
разрешаются как любой `git merge`. Но предпочтительный путь — правка через
`Godot_Template_<ИмяЭтогоПроекта>/` (см. выше), она не конфликтует при pull и явно помечена как
предложение в шаблон.

## Что НЕ входит в `Godot_Template/` (специфично для конкретного проекта)

Код, который нужен только этому проекту и не связан с шаблонными классами (игровая логика
Power_struggle, экраны Life_Operator и т.п.), не должен жить ни в `Godot_Template/`, ни в
`Godot_Template_<ИмяЭтогоПроекта>/` — иначе он потеряется/будет мешать при следующем
`subtree pull`. Держите его в соседней папке (например `GameClass/` в Power_struggle).
